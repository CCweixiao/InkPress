# 知识解释模式

## 现象 → 机制 → 判断

适合解释技术、产品、健康、育儿、效率工具。

结构：

1. 读者能看到或遇到的现象。
2. 背后的机制，用一两层解释即可。
3. 读者应该如何判断、使用或避坑。

## 误区 → 修正 → 例子

适合纠正常见误解。

结构：

1. 先写常见误区。
2. 说明它错在哪里，限制条件是什么。
3. 用一个具体例子修正理解。

## 对比表

适合 A/B/C 方案、工具、平台、功能比较。

移动端表格建议：

- 3–4 列以内。
- 每格短句，不塞长段落。
- 第一列写读者关心的维度，不写抽象分类。
- 表格后补一句“怎么选”，否则只是信息陈列。

## 类比

好类比：

- 只比较结构，不制造错误事实。
- 读者熟悉。
- 能在一句话内说清相似点和不同点。

坏类比：

- 比知识点还难懂。
- 为了有趣牺牲准确。
- 延伸过度，最后变成段子。

## 例子

例子要具体到行为或场景，但不要虚构来源型事实。

可写：

- “一个小团队在选工具时……”
- “家长记录喂养时最容易漏掉的是……”
- “第一次配置自动化的人，通常会卡在……”

慎写：

- 具体公司、医院、机构、数据，除非来源已经提供。
- “很多专家认为”“业内普遍认为”等无来源代言。
