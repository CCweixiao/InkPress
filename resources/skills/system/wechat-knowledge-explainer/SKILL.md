# 公众号知识通俗化

本技能负责“把知识讲通”，不是负责炫技、堆概念或写论文。默认配合 `wechat-writing` 使用，也可以单独输出解释段落、例子、类比或对比表。

## 读取策略

- 普通知识解释：先执行本文件。
- 需要选择解释模型、类比、表格或例子：读取 `references/explainer-patterns.md`。
- 需要最新事实、数据、医学/法律/金融等高风险信息：先加载 `web-research`，并保留来源边界。
- 需要成篇公众号文章：同时加载 `wechat-writing`。
- 需要去 AI 味或终稿精修：同时加载 `de-ai-writing`。

## 工作流

1. 明确读者已有认知：完全陌生、听过名词、用过但不懂原理，还是需要做选择。
2. 找出必须保留的专业事实、限制条件和不能简化错的术语。
3. 把知识拆成“是什么、为什么重要、怎么判断/怎么用、常见误区”。
4. 每个抽象概念至少配一个具体场景、例子、后果或对比。
5. 术语第一次出现时用白话解释，后续保持术语一致。
6. 删除不服务读者判断的背景、分类史、定义链和名词堆叠。
7. 回读检查：普通读者能否复述核心判断，专业读者是否会觉得失真。

## 表达原则

- 先讲读者关心的问题，再讲知识点。
- 先给可感知的现象，再给机制。
- 类比只解释结构关系，不替代事实本身。
- 可以有轻微趣味，但不靠段子、夸张和网络热词。
- 不把“不确定”“取决于条件”的知识写成绝对结论。
- 不用论文式结构：定义、分类、意义、启示。

## 输出方式

- 用户要解释：输出可直接放进文章的自然段或小节。
- 用户要比较：输出移动端可读的 Markdown 表格，列数尽量控制在 3–4 列。
- 用户要例子：给 2–4 个不同场景，不要虚构具体机构、人物或数据。
- 用户要成文：交给 `wechat-writing` 组织全文，本技能提供知识表达骨架。
