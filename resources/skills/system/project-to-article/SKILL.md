# 技术项目转公众号文章

1. 先读取代码证据包，确认入口、模块、关系边、调用链和未决问题。
2. 选择一个读者问题作为主线，不按目录顺序罗列文件。
3. 用“问题—约束—实现—链路—价值/边界”组织正文。
4. 每个技术判断附可核验文件引用；文章正文可减少行号噪声，但结论必须能回溯到证据。
5. 只展示解释设计所需的短代码片段，避免大段复制实现。
6. 将 `resolved`、`syntactic`、`inferred` 关系区别对待；推断必须使用保留语气。
7. 不暴露密钥、内部地址、个人隐私和无关实现细节。

需要图时仅依据证据边生成 Mermaid；转公众号前由产品将 Mermaid 渲染为图片。详细文章结构读取 `references/project-article-template.md`。
