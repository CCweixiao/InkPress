# 技术文档编写

## 工作流

1. 明确文档类型、目标读者、问题范围和需要回答的关键问题。
2. 检查代码证据包的项目快照、入口、模块、调用边和未决问题。
3. 先写结论与系统边界，再写关键流程、模块职责、依赖和限制。
4. 每个实现结论使用 `path/to/file#Lx-Ly` 引用；同一段不堆叠无关引用。
5. 图表只能使用证据包中的节点和边，节点名称与正文术语保持一致。
6. 将静态无法确认的行为列为限制或待核验项，不伪装成运行时事实。
7. 完稿后进行“新读者测试”：读者是否能找到入口、理解主流程、定位关键实现并知道边界。

## 文档结构

- 架构概览：目标、边界、组件、主数据流、关键依赖、限制。
- 功能实现：用户场景、入口、主调用链、状态变化、异常路径。
- 调用链分析：触发点、逐步链路、同步或异步边界、外部依赖、置信度。
- 模块参考：职责、公开入口、依赖、被依赖方、关键文件。
- 依赖分析：模块图、关键边、循环依赖、耦合风险和证据。

## 输出约束

- 输出完整 Markdown；Mermaid 保留为 fenced code block。
- 技术文档修改必须生成提案，不直接覆盖正文。
- 摘要中记录代码快照哈希。项目变化时提示文档可能过期，不自动重写。
- 需要具体模板时读取 `references/document-templates.md`。
