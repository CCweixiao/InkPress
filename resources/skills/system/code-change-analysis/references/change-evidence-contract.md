# Git 变更证据契约

## 证据优先级

1. Diff 中的实现变化与源码定义。
2. 可解析的符号、引用、依赖和调用关系。
3. Commit、PR 描述与测试名称。
4. 文件名、目录名和模型推断。

低优先级信息不能覆盖高优先级证据。PR 或 Commit 声称“完成”但实现证据不足时，使用“提交说明称”而不是事实语气。

## 功能分组

每个分组包含：

- 面向用户或开发者的变化名称。
- 一句话说明变化解决的问题。
- 关联 Commit SHA。
- 关键文件与增删统计。
- 必要的 Diff 或源码位置。
- 兼容性、迁移、回滚和未决风险。

纯格式化、锁文件和生成物不应单独成为功能分组，除非它们确实改变发布行为。

## 常用交付模板

### 更新日志

按新增、改进、修复、工程化和注意事项组织，保持短句和可验证描述。

### 新功能实现介绍

按背景、入口、核心模块、调用链、关键取舍、使用效果和限制组织。

### 公众号技术文章

先解释读者能感知的变化，再展开实现路径；代码证据放在关键结论之后，避免把 Commit 清单直接贴成文章。
