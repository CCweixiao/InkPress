# 只读代码探索

## 原则

- 先发现结构，再搜索符号，最后读取窄范围源码。
- 每项结论附项目相对路径和行号；文件名只能作为线索，不能作为功能证据。
- 区分 `resolved`、`syntactic` 和 `inferred` 关系。动态分派、反射和依赖注入无法确认时明确标注。
- 不调用联网工具，除非用户另行要求研究外部依赖。
- 不请求 Shell、构建、测试、代码执行或写文件工具。

## 探索流程

1. 读取 manifest、README 和有限深度目录树，识别语言、框架、入口和生成目录。
2. 用 glob 找候选文件，用 search 找路由、服务、符号和配置，不做无边界全库读取。
3. 用 symbols、references、dependency graph 和 call hierarchy 建立关系。
4. 对关键边读取定义与调用附近源码，消除同名、注释和测试代码误报。
5. 汇总入口、模块、符号、关系、调用流、文件清单和未决问题。
6. 仅从已确认关系生成 Mermaid，不补画模型臆测的节点或边。

## 证据包要求

返回目标、项目、快照哈希、摘要、入口、模块、符号、关系边、调用流、未决问题、读取文件和截断状态。结论没有代码证据时放入 `openQuestions`，不要写入确定摘要。

语言策略、关系置信度和证据格式读取 `references/evidence-contract.md`。
