## 二、功能架构

### 2.1 判定优先级（guard.ts 单一信任边界）

```
licenseGuard()
  ├─ !isLicenseRequired()          → not-required（放行）
  ├─ readLocalLicenseState() != null → validateLocalLicense()
  │   ├─ 服务端可达 + ACTIVE        → active（30 天滚动宽限）
  │   ├─ 网络错误 + 宽限未过期       → offline-grace
  │   └─ 其他                       → invalid
  └─ 无 license                     → 试用判定
      ├─ inTrial                    → trial（放行）
      └─ expired / tampered         → trial-expired（拦截）
```

### 2.2 数据流

```
┌─────────────┐     每 60s/focus      ┌──────────────────┐
│  浏览器      │ ──────────────────→  │ /api/license      │
│ (Provider)  │ ←──────────────────  │   /status         │
└──────┬──────┘    status + gate cookie └────────┬─────────┘
       │                                            │ signGate()
       │ 页面导航                                   │
       ↓                                            ↓
┌─────────────┐  读 gate cookie   ┌──────────────────┐
│ middleware  │ ──────────────→  │ verifyGate()      │
│ (Edge)      │                  │ HMAC-SHA256 验签  │
└─────────────┘                  └──────────────────┘
   │ allowed=false → 重定向 /license?reason=...
   │ cookie 缺失 → 放行（页面 focus 触发刷新）
```

### 2.3 后台同步调度器（sync-scheduler.ts）

```
instrumentation.register()
  → startLicenseSyncScheduler()
      ├─ 立即（延迟 5s）：syncLicenseAndTrial()
      └─ 每 1 小时：syncLicenseAndTrial()

syncLicenseAndTrial():
  ├─ 有 license state → validateLocalLicense()（刷新凭证 + 滚动宽限）
  └─ 无 license       → evaluateTrial() + probeTrialStatus()
                         （本地评估 + 联网探测，失败不阻塞）
```

## 三、审核重点

### 3.1 试用防绕过（核心安全目标）

| 攻击向量 | 防御措施 | 审核位置 |
|---|---|---|
| 删除本地试用文件重置试用 | 服务端幂等 register：`deviceIdHash` 命中既有记录 → 返回当前 state，不重置起点 | `trial-service.ts:43-72` |
| 修改本地时钟回拨 | `trialLastCheckedAt` 用 `max(now, prev)` monotonic 更新；回拨超 60s → 视为篡改 → expired | `trial.ts:104-130` |
| 篡改本地试用状态文件 | AES-256-GCM 加密（`app-state.enc`），密钥不在代码里 | `trial.ts:63-68` |
| 联网时伪造试用起点 | 服务端 register 后 `applyServerState` 用服务端值覆盖本地（锁定） | `trial.ts:132-147` |

**审核点**：
- `trial-service.ts:47-72`：existing 记录**不重置** `trialStartedAt` / `trialExpiresAt`，只刷新 IP/UA/version
- `trial.ts:109`：时钟回拨容差 60s（NTP 微调安全）
- `trial.ts:141`：`serverRegisteredAt` 一旦设置就不覆盖（`?? null`）

### 3.2 gate cookie 安全

| 属性 | 值 | 说明 |
|---|---|---|
| 签名算法 | HMAC-SHA256（Web Crypto SubtleCrypto） | Node + Edge 均可用 |
| 密钥来源 | `~/.inkpress/.secret`（instrumentation 注入到 `__INKPRESS_GATE_KEY`） | 复用 secret-store 密钥 |
| Cookie 名 | `ip-gate` | httpOnly + sameSite=lax |
| TTL | 5 分钟 | 超时后 middleware 放行，由页面 focus 触发刷新 |
| 回退密钥 | `inkpress-gate-fallback-dev-only` | 仅开发态；生产环境 instrumentation 必须注入真实密钥 |

**审核点**：
- `gate-cookie.ts:62-66`：`toBufferSource` 复制到新 ArrayBuffer（避免 SharedArrayBuffer 类型不匹配）
- `gate-cookie.ts:93`：验签用 `crypto.subtle.verify`（常量时间比较，防时序攻击）
- `middleware.ts:52-53`：cookie 缺失/过期 → **放行**而非拦截（fail-open，避免锁死用户）
- `instrumentation.ts:66-78`：密钥注入失败仅 warn，不 fatal（middleware 会用回退密钥）

**⚠️ fail-open 策略说明**：middleware 对缺失 cookie 放行是**有意设计**——昂贵的 license 检查留在 server route，Edge middleware 只做廉价加速。真正的拦截由 `LicenseGateDialog`（前端全屏弹窗）和服务端 API guard 保证。

### 3.3 离线宽限期变更（72h → 30 天）

| 文件 | 旧值 | 新值 | 说明 |
|---|---|---|---|
| `client-service.ts` | `72 * 60 * 60`（72h） | `30 * 24 * 60 * 60`（30d） | 服务端返回的 `offlineGraceSeconds` |
| `token.ts` | `OFFLINE_GRACE_SEC = 72h` | `30 * 24 * 60 * 60`（30d） | token 常量 |
| `client.ts` | `offlineGraceExpiresAt(seconds = 72h)` | `OFFLINE_GRACE_DAYS = 30` + `fromMs` 参数 | 客户端滚动宽限 |

**审核点**：
- `client.ts:210-211`：每次成功 validate 后 `offlineGraceExpiresAt` 重新计算（`lastValidatedAt + 30d`）
- `client.ts:224-228`：超过宽限期的网络错误消息改为「已超过 30 天离线宽限，请重新激活」
- 30 天宽限意味着：用户最长可离线 30 天，联网后自动恢复

### 3.4 限流策略

| API | 维度 | 限制 |
|---|---|---|
| `/api/v1/trial/register` | 每 IP 每分钟 | 20 次 |
| `/api/v1/trial/register` | 每设备每天 | 5 次 |
| `/api/v1/trial/status` | 每 IP 每分钟 | 30 次 |
| `/api/v1/trial/status` | 每设备每小时 | 1 次（与探测节奏对齐） |

**审核点**：
- `register/route.ts:32-41`：先 IP 限流，通过后再解析 body 做设备限流（避免无效请求消耗 DB）
- `status/route.ts:59-68`：设备限流 1 次/小时，与客户端每小时探测节奏对齐

### 3.5 状态文件命名

客户端试用状态文件使用**中性名** `app-state.enc`（而非 `trial-state.enc`），降低用户手动删除/篡改的发现概率。复用 `secret-store` 的 AES-256-GCM at-rest 加密。

**审核点**：`trial.ts:26` — `TRIAL_STATE_FILE = path.join(inkpressHomeDir(), "app-state.enc")`

### 3.6 LicensePanel 重构

LicensePanel 从**自管理 fetch 状态**重构为**消费 LicenseStatusSync 全局状态**：

- 原先：组件 mount 时 `fetch("/api/license/status")` 独立管理
- 现在：通过 `useLicenseStatus()` 读取全局 Provider 状态（Provider 已在 layout.tsx 挂载）
- 新增 trial 模式显示（剩余天数 / 已结束）
- 新增购买链接（`getPurchaseLinks()`：生产=longoflow.com，开发额外显示 localhost:3001）

## 五、潜在风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| `~/.inkpress/.secret` 不存在 → gate cookie 用回退密钥 | 中 | 开发环境正常；生产环境理论上可伪造 cookie | instrumentation warn 日志可观测 |
| middleware fail-open（cookie 缺失放行） | 低 | 用户可清 cookie 绕过 Edge 重定向 | 真正拦截由弹窗 + API guard 保证，Edge 只是加速 |
| 试用状态文件被删除 | 中 | 本地重新创建，联网后被服务端锁定 | 服务端幂等 register 不重置起点 |
| 30 天离线宽限过长 | 低 | 离线 30 天内可用 | 设计如此；超过 30 天必须联网 validate |
| `deviceIdHash` 碰撞 | 极低 | 不同设备共享试用记录 | 使用 SHA-256 + 多维度指纹（machineId/mac/hostname） |
