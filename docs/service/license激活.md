设计InkPress用户服务端平台，技术栈和inkpress类似，react/TS/node/next.js next-auth体系等，db先用sqllite
1. 平台支持两种角色，管理员和普通用户
2. 仅支持普通用户注册，支持邮箱、密码注册登陆，邮箱注册要生成6位数字验证码（10min有效期）验证邮箱合法性，同时支持github授权认证登录，根据此设计用户信息表，登陆表等
3. 设计license认证机制，目前暂时不支持支付，然后自动获取license码，需要管理员在平台生成key，支持过期时间，1年、3年、5年、自定义年份、永久等，以及限制设备数等
   1）license key 类似UUID，需要一张 license key 表，key值、过期时间、设备数、创建时间，状态（启用、禁用等），key要唯一
   2）license key 激活表，存放key的激活数据，key值，设备的mac地址（唯一标识一台设备），激活后，生成key的激活状态，激活时间，然后开始计算过期时间
   3）InkPres 实现 license 激活功能，输入key，点击激活，上传激活信息，上传成功显示激活成功
   4）InkPres 本地记录激活状态，但每次启动需要刷新验证激活信息，如果license实效，就提醒用户key过期，跳转激活页面，阻断用户后续使用
   5）InkPress 内部需要处理认证机制，非认证要阻断
   6）一些注意事项：限制设备数，尽量保证InkPress的license认证逻辑不要被绕过、改写和破解
4. 在license key基础上设计邀请码机制，为每个登陆用户生成并绑定唯一邀请码，6位字母和数字组合，区分大小写，生成key时可绑定某个用户的邀请码，这样激活后能识别是哪个用户邀请的
5. 接口因为公网暴露，所以安全加密等机制要规划并做好，访问限流保护服务也要做好
